# Agent Mailbox validation record

This public record separates transport materialization, message detection, consumption correctness, runtime wake, and design-only coverage. It uses sanitized case identifiers and rounded findings. Exact operational provenance remains private.

## Evidence classes

| Class | Meaning |
|---|---|
| Measured | Observed directly in a bounded run with consumed-artifact evidence |
| Observed | A specific behavior was seen, but the run does not support a general guarantee |
| Negative | A required capability failed or was not demonstrated |
| Attributed field report | Operationally useful self-report; not independently reproduced here |
| Capability-confirmed | A named host mechanism was inspected in a current runtime; no complete mailbox flow is implied |
| Design-validated | The written contract covers the case; no consumed field run yet |
| Pending | Neither field evidence nor sufficient design evidence supports a stronger claim |

## Aggregate field calibration

Across bounded operational use, more than one miss had the same structural cause: a consumer tracked watcher time or a narrowed current request rather than reconciling all valid addressed messages against durable handling evidence. This supports the mandatory startup order and the rule that filters prioritize but never erase history.

A separate attributed field incident showed that negotiating participant-local Work-or-Listen cadence can form a self-sustaining availability loop. Reusing a room with legacy mode proposals made the loop harder to distinguish from current product work. This supports unilateral local modes, informational no-reply availability state, and fresh conversation roots after resumption.

This is an aggregate attributed finding. It intentionally omits participants, projects, rooms, artifacts, exact timing, identifiers, and raw logs.

## Defects converted into contract rules

1. A watcher that subscribed only to `Created` could miss an atomically rename-published message. The contract requires both `Created` and `Renamed` plus startup reconciliation.
2. Staging a temporary Markdown file beside the inbox allowed a concurrent folder sync to observe it before final rename. The contract requires proven transport-excluded staging on the same filesystem and indexes/synchronizes only the final file.
3. A successful transport result can coexist with a nonfatal indexing warning. Delivery, indexing, and retry-budget exhaustion are reported separately.
4. Cursor absence can rediscover old work. Durable per-message dispositions are authoritative; the cursor is a compact checkpoint/index.
5. Folder materialization, detector notification, message consumption, task wake, and re-arm are separate capabilities. `LISTENING` requires end-to-end evidence for all applicable layers; otherwise the state is `PARKED` or `DEGRADED`.
6. Work-or-Listen cadence is not a shared contract. Each participant owns its mode, horizon, rearm, expiry, and cleanup; peer work is requested through ordinary scoped CTAs.
7. A reused room does not imply a reused conversation. Returning holders rehydrate with `resume → state`, then new work receives fresh `thread` and `request_id` UUIDv7 values; legacy mode proposals cannot restart negotiation.
8. Append-only messages and the mutable single-writer primer need different target rules. Messages require an absent final target; primer updates use compare-before-replace, atomic replacement, and post-write verification. A stale primer is debt, while a missing primer remains a gate.
9. Process absence alone does not prove listener cleanup. The exact run-bound lease must also be absent, and stale-lock recovery must verify the recorded owner identity rather than trusting a PID or process name.
10. Runtime adapters and scripts can carry arena-scoped authority exceptions. Reuse requires an arena/owner/root audit and removal or fresh authorization of every embedded exception.
11. A sender's host-local root hash is compared with the durable binding for that sender's arena/callsign/machine locus, never with the receiver's local root. Different cross-machine mount paths are expected.
12. Per-fingerprint repair damping is insufficient by itself. A bounded lease also needs an aggregate anomaly-reread/notice ceiling, an open depth-1 repair transaction, and a fingerprint wake path when no trustworthy UUID exists.
13. No-overlap lease reclamation and cleanup are ownership-conditional operations: match exact contents, rename stale evidence to a unique tombstone before create-new acquisition, and never let delayed cleanup remove a successor lease.
14. A malformed nonblank NDJSON disposition record revokes readiness. An earlier valid transition may remain diagnostic evidence but cannot authorize deduplication past corrupt tail state.
15. Wire-response disposition and participant-local availability are orthogonal. `expects_reply: false`, `acted` without wire output, and `no-reply-required` do not stop or change a valid bounded listener/schedule; normal durable handling, clean recheck, and re-arm still apply.
16. A re-freeze during an announced independent review invalidates that review boundary. Explicitly cancel or mark the in-flight review superseded, publish the new exact manifest, and request a fresh review; reviewers must not silently straddle candidate generations.
17. Reuse a proven participant-local listener engine or sanitized blueprint before reconstructing its mechanism, but never inherit arena authority, configuration, contract assumptions, invocation proof, or readiness. The executable adapter stays local; a shared blueprint is not an execution surface.
18. Inspect proven compatible listener engines before rebuilding and prefer the least-adequate tier, while treating the tier as a documented capability/cost decision rather than a readiness gate. Mechanical duties and honest failure reporting remain mandatory. Verified owned-resource cleanup earns `STOPPED`; authorized listener-task archival is separate informational status, not a replacement blocker.
19. Native task-message submission is not wake completion. A listener needs a bounded `wake-pending` state that clears only on exact durable primary disposition plus same-run clean recheck, or times out visibly and releases damping for later correctness retry.
20. A no-overlap lease identity includes arena and canonical mailbox root in addition to run nonce, owner, and creation identity. Handler-authorized stale clearing uses the same identity-bound atomic recovery primitive and refuses when that primitive is unavailable.
21. Dedicated-listener task-creation authority is bound to one exact run and consumed at terminal end; it is not standing authority for replacements.
22. Shared work product uses participant-owned `workspace/<CALLSIGN>/artifacts/`; workspace presence is not delivery, scratch is never referenced, runtime state remains local, and legacy flat `artifacts/` is read-only compatibility input.

## Revision checks

Each released revision must parse the base and all shipped optional YON packages, resolve their local references, keep the base usable without a package, verify bounded fallback/cleanup behavior, and pass a public-data privacy review. Record only the sanitized result here; never copy private mailbox paths, participant identities, UUIDs, hashes, exact operational timestamps, raw logs, or private task text into this file.

The previously released layered-package candidate passed parser, semantic-DAG, isolated-install, registered-Lyt read-only, OneDrive read-only reconciliation, scratch, and public-target privacy checks. Each revision that changes Agent Mailbox semantics, packages, or adapters must record its own sanitized verification result before release; previous evidence is not a substitute for checking changed behavior. Pack-only discovery, presentation, or legal changes do not create a new Agent Mailbox evidence claim.

For the `1.6.2` candidate, the base and all three optional packages passed the public parser and semantic-DAG checks. Two fresh repository-read-only workers used one owned synthetic CORE mailbox with different local operating modes. The run produced exactly one no-reply availability notice, exactly one no-reply compatibility state for a seeded legacy mode proposal, no new mode proposal/counter/acceptance/renewal, and a fresh request root with a causal delivery whose artifact hash was independently recomputed. The bounded run stopped cleanly and its link-free temporary tree was removed after evidence capture. It did not test background `LISTENING`, atomic-rename publication, a real sync provider, or resumption from a known prior accepted message.

For the `1.6.6` candidate, the base and all three optional packages passed the strict public parser and semantic-DAG checks; pack lint, generated-spine consistency, public leak guard, candidate version consistency, and patch whitespace checks passed. The unchanged installer entrypoint copied Agent Mailbox into an isolated temporary Codex profile, invoked the public parser, and produced a 12-file snapshot byte-identical to the source under `--no-stamp`; all four installed YON contracts then passed the public parser again. The temporary tree contained no reparse points and was removed completely. Independent cold review covered listener lifecycle, release surfaces, and workspace ownership; one consolidated repair added finite-set wake completion, per-run reused-task authority, full lease identity and retained-lease degradation, portable callsigns, create-once artifacts, immutable successor continuations, workspace privacy, legacy ownership proof, and writer/non-writer primer handling. A same-host sync-share exchange demonstrated causal review delivery and durable disposition, but did not canary wake-pending timeout, cross-host/provider workspace propagation, concurrent pen transfer, retained-lease recovery under the final text, host restart, or every runtime adapter.

The presence of a YON contract proves inspectable structure, not safety or runtime enforcement. The host runtime remains responsible for scheduling, notification, cancellation, and task wake.
