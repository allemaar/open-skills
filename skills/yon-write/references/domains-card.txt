YON Domains & Profiles Card (v2.0)
https://yon.younndai.com

PROFILES — reference-validator @younndai/yon-parser 2.0.2 contract:
Source: dist/types.js PROFILE_PRESETS, FEATURE_TAGS and STRUCTURAL_TAGS;
effective-feature computation: dist/validator.js. This is implementation-version
authority, not a claim about future versions or independently verified spec text.

Profiles are named feature presets, not a linear cumulative hierarchy:
  core       payload, logic, dialogue, sessions
  decl       core + refs
  exec       decl + workflow, delta
  audit      exec + provenance
  cognitive  exec + cognition, perception, goals, memory, affect (not provenance)
  agent      cognitive + temporal, collaboration, composition, governance,
             reactive, signaling (not provenance)
  full       agent + provenance

Structural tags allowed in every preset: DOC, SEC, META, DEF, NOTE, STAMP,
REDACTION, CONSENT, IDENTITY, LOCATION. Logic includes INTENT, SCOPE, RULE,
SCHEMA, CFG, MAP, CHECK. TURN/ACK use dialogue; SESSION/CHECKPOINT/RECOVER
use sessions. AGENT/STREAM use signaling. STAMP is structural even when the
provenance feature is absent; provenance additionally requires rid on referenceable
RULE/CFG/MAP/SCHEMA/STEP/CHECK records.

Default profile is exec. Explicit nonempty document features override the preset;
validator feature options and scenario defaults are fallback bases when applicable.
Then with adds features and without removes them; mode chat also implies dialogue
and sessions, hybrid implies workflow and dialogue. Do not infer a family from
its name or equate structural STAMP permission with provenance bookkeeping.

Examples:
  @DOC ver=2.0 | id=doc | title="Doc" | profile=decl | with=[workflow]
  @DOC ver=2.0 | id=doc | title="Doc" | profile=audit | without=[provenance]
  @DOC ver=2.0 | id=doc | title="Doc" | profile=exec | with=[cognition,memory]

For extended fields load the exact v2.0 yon-read references named in SKILL.md.
Missing or conflicting required authority stops dependent conformance; do not
auto-acquire a parser, invent a registry, or promise all-tag validation.

FORMAT MODES — control printing density (lossless, never removes records):
  canon   Full readability, all optional fields. For humans.
  min     Reduced quoting, cosmetic whitespace stripped. Default for LLM pipelines.
  ultra   Maximum density, structural omission. For cost-critical transport.

Declare in @DOC: fmt=min

fmt=ultra rules:
  - MAY omit profile=exec (default)
  - MUST NOT omit type suffix (:type) — types are always explicit
  - MUST NOT omit ver (always required)
  - MUST NOT omit n:int=N step sequence numbers
  - MUST NOT omit rid or title

KINDS — what the document represents:
  doc       General document
  rule      Constraints / do-nots / policies
  workflow  Multi-step procedure, triggers, tools
  skill     Reusable capability + steps + checks
  sidecar   Repo/project guidance for IDE agents + context
  spec      Formal definition/contract
  context   Raw dumps (logs/transcripts/artifacts)
  memory    Append-only scratchpad / evolving notes
  note      Everything else
  prompt    Direct agent prompt / mission file

DOMAINS — industry-specific record families:
  Declare in @DOC: domain=yon.health
  Records MAY include domain= to override for that record.
