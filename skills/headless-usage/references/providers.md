Last researched: 2026-09-16. Recheck local version/help on each read; documentation changes require maintenance, not guessed flags. Supported sources use the harness's existing login without extracting secrets.

Grok public documentation rechecked 2026-09-17. The native Grok Build 1.0.70 TUI **/usage** route was observed on Windows on 2026-10-25 without sending an inference prompt. This is dated validation, not a current host or account claim. Load [grok-interactive.md](grok-interactive.md) when executing this route.

Modal opening can display a cached mirror while requesting fresh billing data; absent fresh-response evidence, backend freshness is unverified. Codex app-server sequence: start the native executable with `app-server --stdio`; send `initialize` with clientInfo, receive its result, send `initialized`, then `account/rateLimits/read`. Close stdin and observe clean exit after results. Optional `account/usage/read` supplies provider-reported activity, not remaining quota or billed token counts. Never call a reset-credit consumption method. Source: [official app-server reference](https://learn.chatgpt.com/docs/app-server).

Antigravity distinguishes Gemini and Claude/GPT pools. Its status-line data can expose `quota` entries with `remaining_fraction` and `reset_time`, but an existing capture is a cached source. Credits and optional paid overage are separate from subscription windows; do not turn either on. Sources: [usage command](https://antigravity.google/docs/cli/commands/usage), [headless built-ins](https://antigravity.google/docs/cli/headless/), [status-line fields](https://antigravity.google/docs/cli/statusline), [credits](https://antigravity.google/docs/cli/credits).

Claude's structured status-line fields include `rate_limits.five_hour.used_percentage`, `rate_limits.seven_day.used_percentage` and Unix `resets_at`. They may be absent until the first API response. A refresh interval reruns the renderer; it does not create a standalone quota API. Family-specific bars may appear in the interactive screen without equivalent structured fields. `auth status` is authentication information, not quota. Print-mode JSON reports invocation usage and consumes allowance; it is not a remaining-quota probe. Sources: [status-line data](https://code.claude.com/docs/en/statusline), [usage and costs](https://code.claude.com/docs/en/costs), [quota errors and cached usage](https://code.claude.com/docs/en/errors), [headless output](https://code.claude.com/docs/en/headless).

Claude local activity insights cover available local sessions, not necessarily other machines or all account use. Categories can overlap. The insights-generating command can invoke models and must not be run merely to read quota. The usage screen itself was tested with zero API time and zero input/output/cache tokens in a fresh session.

Grok's documented **/usage** command displays usage or billing controls; inspect the displayed account and bucket without changing billing. The tested native TUI presents a Usage limit section with a Weekly limit plan label, percentage and reset label, plus a separate Session usage section. Session usage can finish loading with no model calls recorded; a standalone CLI usage/accounting command does not establish consumer quota. Settings -> Usage documents the shared Chat/Imagine/Voice/Build consumer weekly pool. Record the surface's exact labels and verify percentage direction, display precision and reset timezone. Missing fields remain unknown. Record source and observation time; modal opening and absence of a cache warning do not prove a fresh backend response. Without fresh-response evidence label the reading interactive observation, backend freshness unverified; label prior/manual captures cached with capture time and age. Without usable control, authentication and supervision, return unavailable with the manual action: open Grok Build and run **/usage**, or Settings -> Usage. Subscription status does not establish API credits, and API Console billing/rate limits do not establish consumer allowance. Sources: [official Build commands](https://docs.x.ai/build/modes-and-commands), [consumer usage FAQ](https://docs.x.ai/grok/faq), [API rate limits](https://docs.x.ai/developers/rate-limits). Local procedural evidence, source interpretation and cleanup limitation are in [grok-interactive.md](grok-interactive.md).
