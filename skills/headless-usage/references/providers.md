# Provider evidence

Last researched: 2026-09-16. Recheck local version/help on each read; documentation changes require maintenance, not guessed flags. Supported sources use the harness's existing login without extracting secrets.

Grok public documentation rechecked 2026-09-17; no local Grok CLI or authenticated usage surface was queried.

| Harness | Current route | Limits and interpretation |
| --- | --- | --- |
| Codex | Desktop `get_usage_limits`, or app-server initialization then `account/rateLimits/read` | Prefer `rateLimitsByLimitId`; legacy `rateLimits` is a fallback. Null windows are unknown. Separate named buckets may have different windows. |
| Antigravity | Standalone print command `agy -p /usage --print-timeout 15s` | Current CLI 1.2.4; quota-reader behavior was last tested on 1.2.3 and emits four tab-separated columns: pool, window label, percent remaining, UTC reset. Do not combine this built-in command with stream-json input. Reject unfamiliar schemas. |
| Claude Code | Interactive **/usage**, with **/stats** documented as an alias | Current CLI 2.1.272; interactive quota-reader behavior was last tested on 2.1.260. Wait for live refresh; the first rendering can contain cached numbers. An ANSI text dump can include cursor updates that change earlier digits, so stripping escape codes is not a reliable parser. |
| Grok Build | Existing authenticated interactive **/usage**, or web/mobile Settings -> Usage | Observe only with available terminal/browser control. The consumer weekly pool is shared across Chat/Imagine/Voice/Build. API Console billing and rate tier are separate. No standalone machine-readable quota endpoint or bundled direct-reader support is verified. |

Codex app-server sequence: start the native executable with `app-server --stdio`; send `initialize` with clientInfo, receive its result, send `initialized`, then `account/rateLimits/read`. Close stdin and observe clean exit after results. Optional `account/usage/read` supplies provider-reported activity, not remaining quota or billed token counts. Never call a reset-credit consumption method. Source: [official app-server reference](https://learn.chatgpt.com/docs/app-server).

Antigravity distinguishes Gemini and Claude/GPT pools. Its status-line data can expose `quota` entries with `remaining_fraction` and `reset_time`, but an existing capture is a cached source. Credits and optional paid overage are separate from subscription windows; do not turn either on. Sources: [usage command](https://antigravity.google/docs/cli/commands/usage), [headless built-ins](https://antigravity.google/docs/cli/headless/), [status-line fields](https://antigravity.google/docs/cli/statusline), [credits](https://antigravity.google/docs/cli/credits).

Claude's structured status-line fields include `rate_limits.five_hour.used_percentage`, `rate_limits.seven_day.used_percentage` and Unix `resets_at`. They may be absent until the first API response. A refresh interval reruns the renderer; it does not create a standalone quota API. Family-specific bars may appear in the interactive screen without equivalent structured fields. `auth status` is authentication information, not quota. Print-mode JSON reports invocation usage and consumes allowance; it is not a remaining-quota probe. Sources: [status-line data](https://code.claude.com/docs/en/statusline), [usage and costs](https://code.claude.com/docs/en/costs), [quota errors and cached usage](https://code.claude.com/docs/en/errors), [headless output](https://code.claude.com/docs/en/headless).

Claude local activity insights cover available local sessions, not necessarily other machines or all account use. Categories can overlap. The insights-generating command can invoke models and must not be run merely to read quota. The usage screen itself was tested with zero API time and zero input/output/cache tokens in a fresh session.

Grok's documented **/usage** command displays credit usage or billing controls; inspect the displayed account and bucket without changing billing. Settings -> Usage shows the consumer weekly percentage and reset schedule. Record source and observation time; call a current surface live only when it reports current data. A prior or manual capture is cached with its capture time and age. Without terminal/browser control or an existing authenticated surface, return unavailable and the manual action: open Grok Build and run **/usage**, or open Settings -> Usage. Missing reset or percentage fields remain unknown. Subscription status does not establish API credits, and API Console billing/rate limits do not establish consumer allowance. Sources: [official Build commands](https://docs.x.ai/build/modes-and-commands), [consumer usage FAQ](https://docs.x.ai/grok/faq), [API rate limits](https://docs.x.ai/developers/rate-limits).
