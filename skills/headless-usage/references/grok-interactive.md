# Grok Build interactive quota read

Load this reference only for a Grok interactive usage query. Use existing authentication and the installed native executable discovered on the current host. This procedure sends no inference prompt; it does not promise effect-free startup because configured hooks and MCP integrations may load.

## Bounded procedure

1. Prefer an existing authenticated TUI or browser usage surface. If starting a TUI, verify the native executable, current version/help, known working directory and current supervisor support. Retain the PTY/session handle, owned process identity, finite deadline and scoped cancellation path. A 60-second deadline is a starting recommendation, not permission to abandon a live process. If supervision or authentication is unavailable, return the exact route gap.
2. Inspect startup and trust prompts before input. Accept directory trust only when that exact known directory is already authorized for this run; otherwise stop at the prompt. Never accept permission-default, billing, purchase or training opt-in changes to read usage. A startup failure, hook failure or login prompt must be reported accurately; do not send a work prompt to test access.
3. Once the normal TUI input is ready, type **/usage** and send Enter. Wait within the deadline for refresh/loading states to finish. Inspect the fully rendered terminal screen, including cursor updates. A regex that merely strips ANSI escape codes can preserve overwritten digits or stale screen text and is not reliable evidence of the final value.
4. Capture the displayed quota section, bucket/plan label, raw percentage, reset label, observation time and freshness. Keep Usage limit separate from Session usage. If the screen does not define whether its percentage is used or remaining, preserve the raw value and mark direction unknown until the current surface or an applicable verified source establishes it. Preserve display precision: a floored integer used percentage describes a range, not an exact remaining value. Convert reset times only when the source timezone is verified; otherwise preserve its literal label and mark timezone unknown. The modal can open from a cached mirror while requesting fresh billing data; neither opening it, finishing session-accounting loading nor absence of a cache warning proves backend quota freshness.
5. Close the usage modal with Escape as a separate input event. Use the current TUI's documented exit action and verify exit through the retained supervisor. In the tested version, Ctrl+Q twice displayed a goodbye message, but the process remained alive. Goodbye text is not proof of termination. If still alive, verify the owned PID, executable path and creation time before scoped termination; inspect owned children and observe the PTY/process completion. Report forced termination and its exit status as a cleanup exception, not normal exit. Never kill all processes by name or abandon the handle at deadline.
6. Return a dated interactive observation and name any cleanup exception. Use live only when a fresh backend quota response is established; otherwise label it **interactive observation; backend freshness unverified**. A prior/manual capture is cached with capture time and age. Keep raw diagnostics private. If the screen remains loading, quota fields are absent or cleanup cannot be established, return partial/incomplete evidence with the exact gap and the manual action: open Grok Build and run **/usage**, or Settings -> Usage.

## Dated validation and limits

On Windows with native Grok Build 1.0.70 on 2026-10-25, a supervised normal TUI in an authorized scratch directory required a directory-trust prompt. After authorized acceptance, **/usage** opened a Usage limit modal containing a Weekly limit plan label, percentage and reset label. Session usage refreshed from loading to a no-model-calls state. No inference prompt was sent. A startup hook failure was also visible, so this observation does not establish that startup hooks or MCP integrations are absent or harmless.

Escape closed the modal. Ctrl+Q twice showed goodbye, but the owned native process remained alive. Its exact identity and absence of owned children were verified before scoped forced termination; the PTY then completed with exit code 1. This validates an interactive read with a cleanup exception, not a clean exit guarantee. Revalidate exit behavior on the current version.

This is procedural evidence only. It contains no reusable account allowance, subscription entitlement, executable/profile path or current quota snapshot. CLI session accounting, API Console billing/rate limits and consumer subscription allowance remain distinct. No standalone machine-readable consumer quota endpoint or bundled Grok direct-reader support is verified.
