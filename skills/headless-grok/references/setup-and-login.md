# Lazy setup and subscription login

Load this reference only for an absent CLI, required login, or an explicit setup request. The execution workflow uses existing state and stops its dependent route on missing access. Setup is a separate workflow with explicit Handler authorization for installation or login; discovery never authorizes either action. Reuse current authorization that already covers the exact setup action without asking again. Reuse an existing selected consumer login without starting a new login.

1. Discover the target OS, executable and supported nonsecret status/help surfaces. Never inspect credential stores or print secret values. Check only presence and scope of route variables, including `XAI_API_KEY`, `GROK_API_KEY`, `GROK_MODELS_BASE_URL`, `GROK_MODELS_LIST_URL` and `XAI_API_BASE_URL`; unexpected routing stops execution for review.
2. For an absent CLI, describe the exact official installation source and target changes, then obtain installation authorization. Use only the current [official Grok Build instructions](https://x.ai/build) and [CLI documentation](https://docs.x.ai/build/overview). The reviewed Windows source on 2026-10-25 was `https://x.ai/cli/install.ps1`. Download and review the current installer before running it. Record its source, requested version/channel, target paths, PATH/configuration changes and process deadline. Do not substitute an unofficial package or infer that another platform uses this installer.
3. If login is required, obtain or reuse authorization for the current help-supported consumer browser/device login. The tested consumer command was `grok login --oauth`; verify current `grok login --help` first. Keep the interactive handoff visible to the Handler, bounded, monitored and cancellable. The Handler completes their own sign-in. Do not copy credentials or launch login in an unattended worker. Verify the resulting supported nonsecret status before returning to execution preflight. The tested `grok models` surface provided nonsecret login/model status; use it only after checking current help.
4. Preserve the subscription route. Do not add an API key, enable API billing, buy credits or fall back to API access. A subscription does not establish API entitlement. An explicitly requested API workflow requires separate authorization and budget outside this setup route.
5. Return to full execution preflight after setup. Installation success proves neither login nor model access. Login success proves neither remaining quota nor permission isolation. A separately authorized inference trial is required to establish execution behavior.

Keep global settings unchanged unless the Handler explicitly authorizes that separate change. Run-scoped environment values and a reviewed workspace configuration belong to the bounded run specification, not a global setup repair. This reference does not amend the shared [access contract](access.md).

On the tested Windows installation, the binary was `%USERPROFILE%/.grok/bin/grok.exe`. This is a dated discovery hint for stale parent PATH, not an assumed location. Verify any explicit candidate exists and use its resolved path; do not edit PATH merely to make discovery pass.
