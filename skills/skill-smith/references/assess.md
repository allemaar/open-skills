# Assess and boil

Load for a skill audit or content simplification. Read [authoring](authoring.md); load [routing](checks/routing.md) only for invocation/metadata and [portability](checks/portability.md) only for dependencies, references, consumed form or requested drift. Target size does not make all dimensions mandatory.

1. Establish the intended task and representative success and failure. Read complete in-scope sources and affected callers. Trace selected routes and what a consumer must actually read. Freeze boundaries and report sampling or unresolved sources.
2. Identify material defects with locations and consequences: contradictory rules, competing owners, generic advice, duplicate instructions, missing inputs/stops, hidden dependencies or broken routes. Material means changed authority, safety, permission, visibility, scope, routing, output, evidence, recovery, portability or recurring load. Omit taste-only edits.
3. For findings keep disposition (`KEEP`, `CUT`, `REWRITE`, `MOVE`, `SPLIT`, `ENFORCE`), conflict (none or competing clauses) and severity (blocking/high/medium/low) independent. Include strengths without manufacturing balance. Use ENFORCE only with an objective marker and a mechanism that improves reliability; keep policy the agent still needs to see. Combine repeated instances.
4. Recommend keep / improve / restructure and the smallest useful changes, compared with leaving it alone. Name exact files and behavior that must survive. For overlapping skills, use [consolidate](consolidate.md); don't merge merely to reduce the count.
5. Remain read-only unless edits are requested. If authorized, use [write](write.md), then [evaluate](evaluate.md). Report affected cases and gaps; compression is successful only when task quality and safeguards survive.
