# Guided use and progressive help

Begin at the user's requested depth. For first use, explain the physical library, family prefix and per-machine links in a few sentences. Use metadata-only live inventory; show names and one-line purposes, then the capability map. Generic help never runs installation status. Without Node, label a manual read-only frontmatter inventory and state that installation is unverified. For an experienced user's clear request, enter its procedure directly.

| Level | Show |
|---|---|
| Overview | Family purpose, skill count, available capabilities, material blockers |
| Selected capability | Inputs needed, what changes, the next decision and expected result |
| Procedure | Selected reference and exact paths/commands, only if needed for execution or explanation |
| Troubleshooting | Relevant native adapter, errors and recovery evidence |

Before first installation, ask global or project-local scope, the actual project if local, and unresolved custom harness locations. Confirm this user's physical source, not a colleague's path. Preview targets before creating roots or links. Other machines do the same independently.

After creation or installation, tour the result: manager path, shared README/configuration, selected harness targets, private receipts and how to ask for help. After authoring/import/adoption, show the skill name, purpose, changed files, version/provenance and actual link outcomes. Use examples grounded in the current inventory.

When creating a skill, offer the optional per-skill improvement loop once through authoring. “Assess/boil this skill” checks clarity, useful detail and lazy loading before proposing edits. “Compare upstream” uses an already acquired incoming folder offline. “Recover this operation” loads only the relevant recovery row. These capabilities require no external skills or harness-specific question tool.

The helper's `help` returns a compact map; `help --topic author` (or create/list/import/adopt/check/retire/upgrade and its recognized aliases) expands that topic. Creating or editing a family skill uses draft-and-publish authoring. `init` creates a library and generator `upgrade` needs the inspected creator; those are not standalone manager operations. The agent supplies the conversational walkthrough; the helper does not run an interactive terminal questionnaire. Questions should carry a recommendation where useful and allow free text. Do not require command knowledge or display every internal setting at once.

Do: route from outcomes and real inventory. Don't: load every skill body to show a menu. Success: the user understands the next action and the scope it affects. Failure: unexplained command dumps, repeated questions or a catalog mistaken for verified installation.
