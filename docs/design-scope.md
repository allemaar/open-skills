# Deferred orchestration scope

These are separate future capabilities, not restrictions on the smaller supported workflows.

## Persistent cross-task decision maps

Defer persistent cross-task decision-map/state orchestration until ownership, concurrency, stale evidence, action authority and bounded resolver jobs have a coherent contract. Ordinary selected decision records remain within their existing owner.

Revisit for a named scope after isolated tests demonstrate conflict protection, stale-source handling, interrupted-update recovery and observable resolver timeout/cancellation. Map content must never authorize its own execution.

## General executable workflow wizards

Defer general executable workflow-wizard generation until shell quoting, secret input, temporary files, exact destinations/external targets and restart/recovery use tested mechanisms. Existing skill-library-creator guided setup and template generation remain separate capabilities.

Revisit for a named host/target after wrong-target, secret-handling, interruption/restart and conditional recovery cases pass without overwriting concurrent work. A generated script alone is insufficient.

## External tracker orchestration

Defer external-tracker publication/scheduling orchestration until authenticated adapters, graph/cycle/frontier rules, idempotent partial publication, bounded workers/cancellation and verified integration state are established. Drafting specifications or PR evidence remains separate.

Revisit after isolated tracker tests demonstrate cycle rejection, duplicate/partial-publication replay, cancellation and integration-state reconciliation. Access alone does not establish safe orchestration.
