# Make a useful test-driven change

Use this method when an authorized behavior has an independently specified expectation and an observable seam. It does not authorize implementation or replace an existing executor's judgment rules.

## Prepare and choose fit

Required skill install set: none. Read this recipe directly. You need the task's authority and constraints, relevant source, repository test rules and an available suitable runner. No package, paid service or subagent is required; missing tools stop dependent execution, not trigger installation.

Reuse an agreed public seam. Resolve a missing choice under the active execution contract: a strict approved-plan executor still surfaces every unspecified decision. Derive the expected result from a requirement, trusted fixture or worked calculation before treating implementation output as an oracle.

If no informative behavioral oracle exists, use appropriate configuration, integration, static or manual checks and explain the limit. Configuration and presentation work are not categorically exempt when they do have testable behavior. Do not manufacture a failing assertion merely to claim TDD. A direct explanation or diagnosis-only request does not authorize this implementation loop.

## Run one slice

1. Choose one behavior and a plausible wrong result the test must distinguish.
2. Write the targeted check and run it. Confirm the failure concerns that behavior; syntax, import or fixture failures are setup problems.
3. Repair setup only within authority, then observe the informative failure.
4. Implement the smallest coherent authorized slice and rerun the check.
5. Continue with the next needed behavior, informed by the result, rather than writing a horizontal batch for unbuilt work.

Use appropriate boundary fixtures or doubles and state what they do not model. Avoid private-plumbing assertions and implementation-shaped expectations merely for coverage. Safe refactoring is allowed only within scope with preserved behavior; it is neither mandatory nor universally forbidden.

Preserve unique existing coverage. A new boundary test does not prove older tests redundant or authorize deleting them. Before edits, inspect leaves and ancestors without following redirects; refuse unsafe paths. Reread current content, preserve user edits and recovery material, and stop overlapping conflicts rather than replaying stale content.

## Close

Run targeted tests before required broader project gates, honoring restrictions on automatic commands. Check the actual selected candidate, including relevant staged/uncommitted work. Report behavior, independent expectation, observed red reason, actual checks/results and unverified surfaces. Passing one test supports only its exercised behavior. Stop at the task's bound, missing capability or scope boundary.

No installation, destructive cleanup, commit, publication or deployment is implicit.

## Worked expectation and request

Rule: apply a 10% discount to 80 currency units. Worked independently: discount = 8; payable = the literal 72. A check expecting 72 at the pricing interface can reject a missing discount. Calling the production discount helper to compute the assertion cannot supply independent evidence.

Request: “Use this recipe for the authorized discount change. Reuse agreed seams, derive expectations independently, observe an informative failure and implement one slice. Run required checks, report unavailable evidence and do not commit.”

Flow: fit or alternate checks -> independent expectation -> informative failure -> authorized slice -> targeted and required broader checks -> evidence report. No subagent step is prescribed. Optional related guidance: [plan-execute](../skills/plan-execute.md) retains its stricter contract when selected; it is not required for this recipe.
