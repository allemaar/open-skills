# Workflows

Start with one job. Each recipe gives you the context to bring, a request to try, the expected result and the point where it should stop. Read the linked skill sources before using a procedure. Following a recipe does not automatically run its successors.

| What you need | Recipe | What you leave with |
|---|---|---|
| Get decision-relevant answers from someone else | [Prepare an expert questionnaire](prepare-an-expert-questionnaire.md) | A recipient-ready draft, without sending it |
| Understand a recurring activity before automating it | [Describe a useful workflow](describe-a-workflow.md) | Inputs, roles, ordinary steps, exceptions and open choices |
| Develop a document together | [Co-write a document](co-write-a-document.md) | Agreed text that preserves sources and intervening edits |
| Change a behavior with a useful test | [Make a test-driven change](test-driven-change.md) | An independent expectation, an informative failure and scoped verification |
| Make an agreed architecture rule observable | [Enforce module boundaries](enforce-module-boundaries.md) | Allowed and forbidden controls for the claimed importer scope |
| Explain what a change does and what was checked | [Write PR evidence](write-pr-evidence.md) | A complete draft tied to the selected candidate and available evidence |
| Capture a repeated task as one reusable skill | [Create a small skill](create-a-small-skill.md) | A scoped draft or an existing-skill reuse recommendation |
| Give a related set of skills its own home and manager | [Create a portable skill library](create-a-portable-library.md) | A setup preview, then the exact authorized creation and installation scope |

The first six recipes have no required skill install set. They still need the sources, authority and tools named in their prerequisites. Skill and library creation use the authoring skills named in those recipes. A missing tool is a limit to report, not permission to install it. None of these recipes grants permission to publish.
