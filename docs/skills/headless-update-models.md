# headless-update-models

[All skill guides](../README.md) · [Catalog](../../SKILLS.md)

The headless model guide may be based on dated prices or model availability. An explicit refresh gathers current primary evidence, updates the canonical selection data and projects it to its supported consumers with per-source dates.

Existing installed copies are refreshed only within the verified established cohort, with retained preimages and parity checks. A new installation is a separate request.

## Where it fits

Use this to refresh model guidance; live quota and usage questions belong to the usage workflow.

**Family:** Orchestration & dispatch. **Subagents:** No subagent step prescribed.

## When to use it

- Update family model guidance
- Refresh stale provider evidence

## When not to use it

- Live quota checks or benchmark inference

## How to use it

Start with a concrete request. For example:

```text
/headless-update-models Refresh provider model, effort and pricing guidance, then check the established installed copies against the updated source.
```

## Flow

1. Identify the canonical source and exact write cohort, including established copied or plugin installations.
2. Gather current primary model, pricing and benchmark evidence without benchmark inference.
3. When refreshing an existing installation, derive and stage only its verified established cohort; never add a member implicitly.
4. Projection counts derive from the owner’s current asset and consumer arrays.
5. The explicit update request authorizes that scope; new installations require a separate request.
6. Update dated records, project them to registered headless consumers, and refresh the selected established installations through verified installers while retaining preimages.
7. Verify source and installed parity and report gaps.

## Common questions

**Can a benchmark for one model stand in for another?**

No. Report available primary evidence and gaps without inferring missing benchmark results.

**What if only some sources can be checked?**

Record each attempt and gap separately. Advance the last successful verification time only for sources actually checked, and report partial coverage.

## It is working when

- The update records source dates, evidence coverage and unresolved gaps.
- The canonical source, selected projections and established installations are checked for parity.
