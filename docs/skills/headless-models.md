# headless-models

[All skill guides](../README.md) · [Catalog](../../SKILLS.md)

You need a model for a task, but a benchmark ranking does not establish runtime access or workload cost. Headless-models filters by output, tools, privacy, budget and latency, then compares dated performance evidence with current availability.

Benchmark cost, API pricing and subscription quota are distinct. Coding results inform comparable coding work, not prose or research accuracy; an unmeasured task family stays unmeasured.

## Where it fits

Use it to recommend a setup. The updater owns a separate refresh, and each provider skill owns execution details.

**Family:** Orchestration & dispatch. **Subagents:** No subagent step prescribed.

## When to use it

- Compare providers for a task
- Choose a model and effort

## When not to use it

- Refreshing the catalog itself

## How to use it

Start with a concrete request. For example:

```text
/headless-models Compare locally available models for a read-only review of this package within my stated time and quota limits.
```

## Flow

1. Define output needs and constraints
2. Check current provider evidence and local availability separately
3. Compare suitable choices and disclose cost uncertainty
4. Recommend a supported route without changing the caller's selection
5. Preserve dated login ordering and use live discovery for current access; no historical observation proves present entitlement.

## Common questions

**Does a listed model have proven inference access?**

No. Catalog visibility, entitlement and successful execution are distinct observations.

## It is working when

- The recommendation names the setup, relevant evidence dates, cost basis and availability gaps, with an alternative when its trade-off is useful.

## Subagents

The skill defines no subagent step; host rules still apply.

This describes the skill's own workflow. Available tools and the runtime's permission rules still apply.

## What you get

A sourced model and effort recommendation.
