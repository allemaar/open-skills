# map-rules

[All skill guides](../README.md) · [Catalog](../../SKILLS.md)

You are about to organize Markdown and need to know which rules govern the scope. Map-rules resolves the scope contract and routes the operation to relevant ownership, naming, navigation or other references before assessment or change.

An existing house dialect can be preserved, but eligible members still need one owner and reciprocal curated navigation. Detection is evidence, not automatic permission to restructure a tree.

## Where it fits

Use it to load organization rules. Map-this performs a bounded organization cycle; sync and vault identity have other owners.

**Family:** Obsidian & vault. **Subagents:** No subagent step prescribed.

## When to use it

- Assess a candidate Markdown scope
- Create, move or link governed notes

## When not to use it

- Sync or topology operations

## How to use it

Start with a concrete request. For example:

```text
/map-rules Determine the scope and ownership rules for organizing notes under this selected project folder.
```

## Flow

1. Read the scope reference before assessing the work.
2. Select and read every applicable routed reference and confirm required load markers; stop if required content is missing.
3. Propose existing-file changes for explicit user selection; a new file and its reciprocal owner-map join are one approval set.
4. Apply the loaded rules only within that selected scope.
5. Use the owned M3 grammar and address precedence; invalid contracts block dependent resolution and healing.
