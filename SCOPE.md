# Scope

Open-skills is a public collection of reusable skills and practical recipes for people and agents. Readers should be able to select one useful capability without adopting an entire process, a private setup or a paid provider.

A skill earns its place when it has a useful independent invocation, a clear result and boundaries readers can understand. A variation that composes from existing skills belongs in a recipe or conditional route when that is sufficient. Complexity is justified by the task, not a fixed line count or a preference for more files.

Changes should preserve the behavior and safeguards outside their stated scope. User-facing explanations, source procedures, discovery and release notes must agree. Source checks, installation, runtime pickup and practical outcomes are distinct claims.

Bug reports are most useful with the skill/version, relevant runtime, a redacted request, expected and observed behavior, and any minimal reproduction. Questions and examples can use repository Discussions. Contribution and security routes remain in CONTRIBUTING.md and SECURITY.md.

Persistent shared decision maps, general executable wizards and external tracker orchestration remain deferred pending their documented ownership, recovery and integration requirements in docs/design-scope.md. A deferral is revisitable; it is not a claim that the capability has no value. Small interviews, selected records, guided library setup and spec or PR-evidence drafts remain available.
